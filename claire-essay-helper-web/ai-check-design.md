# AI 率 + 查重率检测 · 设计规格（v1.0 草案）

> 目标载体：`worker.js`（单文件 Cloudflare Worker）+ `ai-check.html`
> 交付形态：ES Module 形式的纯 JS（零依赖，浏览器 / Worker 双端可跑）

---

## 0. 先划边界（这三条决定了整个技术选型）

| # | 事实 | 对设计的影响 |
|---|---|---|
| 1 | 「AI 率」不存在客观真值。它是某家检测器的黑盒输出，各家分数能差 30 个点。OpenAI 自己在 2023-07 关掉了 AI 分类器，理由是准确率不够。 | 站内只能输出**「AI 风格指数」**，不能叫「AI 率」。给档位 + 理由 + 高亮，不给"87% 是 AI 写的"这种伪精确结论。 |
| 2 | 「查重率」= 语料库规模。知网亿级文献，Turnitin 有学生论文库。**没有库就没有查重**，只有"和你给的文本比"。 | 必须做**多档来源**：粘贴参考文（零成本）→ 站内历史库（要建库）→ 公网检索（要 API）。UI 上写明"自建库相似度，不等于知网重复率"。 |
| 3 | 这个站的用途是**改前 → 改后看趋势**（`ai-check.html` 现有提示已经这么写了）。 | 检测必须是**确定性的**：同一段文本两次检测必须同分。所以规则法为主，模型只能做可选增强，不能做唯一判据。 |

补充：不要让 DeepSeek 自己去判"这段是不是 AI 写的"——同族模型判断自己的输出有系统性偏差，而且不可复现。**正确用法是把规则命中的句子喂给它做改写建议**，复用现有 `/api/chat`。

## 1. AI 风格指数：分层规则引擎

### 1.1 处理管线

```
原文
 ├─ P0 预处理：剥代码块 / 参考文献段 / 目录 / 页眉脚注标记
 ├─ P1 分句：中文 [。！？!?；;…] / 英文 [.?!]，保留 {start,end} 偏移
 ├─ P2 分词：Intl.Segmenter（zh word / en word），无字典依赖
 ├─ P3 统计基元：句长序列、段句数、字词频、n-gram
 ├─ P4 8 类信号打分（句级 + 文档级）
 ├─ P5 聚合 → 0-100 + 档位 + 置信度
 └─ P6 归因 → 命中短语带 offset，前端高亮
```

**偏移必须守恒**：归一化（全角转半角、去空白）时维护 index map，否则高亮会错位——这是这类功能最常见的 bug。

### 1.2 信号与权重

| ID | 信号 | 权重 | 计算方式 | 疑点阈值（初始先验，需校准） |
|---|---|---|---|---|
| S1 | **套话模板密度** | 22 | 命中词表次数 ÷ 千字 | <3 正常；3–8 线性；>8 拉满 |
| S2 | **句长节奏（burstiness）** | 18 | CV = σ/μ（句长）；辅以相邻句长差均值/均值 | 中文 CV<0.30 高疑、0.30–0.42 中、>0.45 正常 |
| S3 | **段首连接词规范度** | 12 | 以连接词开头的句子占比；连续 3 句都这样 → 额外加成 | 占比 >0.35 疑 |
| S4 | **具体性 / 抽象度** | 14 | (数字·年份·%·专名·书名号·地名) 每百字；抽象后缀词（性/化/度/感/力/主义/体系/维度/层面）占比 | 实体 <1.5/百字 且抽象词 >4% 字 → 疑 |
| S5 | **词汇多样性 MATTR** | 10 | 窗口 100 词的移动 TTR 均值 | 中文词级 MATTR<0.74 疑（英文 <0.68） |
| S6 | **结构平行 / 三段式** | 10 | 首先…其次…最后 / 第一…第二 / 一方面…另一方面 / On one hand…；或连续 ≥3 句长度落在 ±15% 同一区间且开头同构 | 命中即计 |
| S7 | **自我重复** | 8 | 任两句 3-gram Jaccard>0.5（非引用）；段首句互为同义重复 | 出现 ≥2 次计 |
| S8 | **排版 / 标点痕迹** | 6 | 段落句数 CV<0.25；中文里混英文标点；「——」密度；每段末都是总结句 | 命中 ≥2 项计 |
| S9 | **人类痕迹（减分）** | −15 上限 | 口语词（说实话/其实/我查过）、自我指涉、具体个人经历细节、非常规搭配、轻微病句 | 逐项 −2~−4 |

> S1 词表是这套东西里性价比最高的一项，建议中文 60 条、英文 45 条起步。中文示例：
> 综上所述、总而言之、值得注意的是、不难发现、毋庸置疑、众所周知、随着…的发展、在当今社会、起到了重要作用、具有重要的意义、发挥着不可替代的作用、多维度的、多个层面、不仅…而且、首先/其次/最后、换言之、从某种程度上、在一定程度上、日益凸显、至关重要、不可或缺、相辅相成、密不可分、具有深远影响、为…提供了新的视角、本文旨在、在…背景下、持续优化、全面提升、有效促进、有力推动、深入贯彻
> 英文示例：delve、furthermore、moreover、it is important to note、in today's fast-paced world、in the realm of、plays a pivotal/crucial role、a testament to、underscore、multifaceted、nuanced、robust、leverage、tapestry、landscape、navigate、shed light on、pave the way、at the forefront of、intricate、holistic、paramount、meticulous、foster、facilitate、encompass、overarching、seamless、ever-evolving、cutting-edge、synergy、paradigm shift、in conclusion

**注意**：词表里有些词在学术写作里本身是合法的（不可或缺、相辅共成）。它们是**信号不是证据**，所以只做加权，不做"这一段是 AI 写的"判定。

### 1.3 归一化与聚合

```
norm(信号) = clamp((x - lo) / (hi - lo), 0, 1)        // 反向信号（如 CV）取 1-x
句级分   = Σ(weight_i × norm_i) − humanBonus          // clamp 0..100
文档分   = clamp(0.55 × 字数加权均分 + 0.45 × 高分句(前30%)加权均分)
```

取 `0.45` 权重的"高分句"是为了防止长文把少数 AI 段落稀释掉——实际写作里常常是"开头结尾自己写、中段 AI 凑字数"。

```
置信度 = 基础值(字数) − 修正(引用/公式/列表占比)
  <300 字 → 0.30，UI 明说"文本太短，不建议看分数"
  300–800 → 0.60
  >800    → 0.85
```

档位：`0–34 低 / 35–59 中 / 60–79 偏高 / 80–100 高`

### 1.4 校准（别跳过这步）

上面的数字都是**先验值**，第一版一定不准。做法：

1. 收集 120–200 篇样本：人类写作 60 篇（Claire 自己写的 + 同学写的）+ 各模型生成 60 篇 + 人机混写 40 篇。
2. 用规则算出 8 维特征，跑逻辑回归拟合权重，看 ROC-AUC。AUC < 0.72 说明规则太弱，别急着上线。
3. 校准后**固定版本号**（`rules v1.0`）写进结果里，否则跨版本分数不可比，趋势功能就废了。

**权衡**：纯前端跑规则 = 用户能在控制台看到全部权重，也就意味着能被针对性绕过。要"透明可解释"还是要"抗规避"，二选一。建议前端只展示档位和命中的原句，权重表放 Worker 侧。

## 2. 查重：三层，从便宜到贵

### 2.1 Layer 1 —— 字面重合（核心，必做）

```
归一化：NFKC → 全角转半角 → 去空白 → 去标点 → 英文小写 → 数字统一
切片：  中文 k=13 连续字；英文 k=8 连续词
哈希：  FNV-1a 64bit，存 Set<hex>
相似度：containment = |A∩B| / |A|        ← 分母用"待检文"，表示"我有多少是别人那儿来的"
```

选 `containment` 而不是 `jaccard`，因为 Jaccard 会被"两篇长度差异大"系统性压低，而用户关心的是"我这篇里有多少重复"。

**定位**：rolling hash + `Map<shingle, positions[]>`，命中后向两侧扩展比对，合并相邻命中为 span，只报 ≥13 字的连续片段。

**排除项**（必须先剥，否则误报爆炸）：
- 参考文献段、引用块（`"…"` / `(Author, 2020)` / `[1]` 所在句）
- 目录、题目、致谢模板、公式、纯列表
- 长度 <13 字的短语（天然匹配不上）
- **高频通用 shingle 白名单**（"随着社会的发展"这类）→ 用 IDF 加权：在站内库里出现频率高的 shingle 降权甚至不计

IDF 这一步很关键。不做的话，两篇同题目论文会互相报 30% 重复，全是废话。

### 2.2 Layer 2 —— 语义近似（洗稿检测，可选）

- 句级 embedding（Workers AI `@cf/baai/bge-m3`，或硅基流动/OpenAI 的 embedding）
- 判据：余弦 > 0.88 **且** 字面 containment < 0.3 → 标"疑似改写"
- 单独一栏「改写相似度」，**不计入总重复率**
- 理由：同一事实的常规表述本来就相似（"气候变化导致海平面上升"人人这么写），语义相似 ≠ 抄袭

### 2.3 Layer 3 —— 比对来源（决定这个功能有没有用）

| 档 | 来源 | 成本 | 能查出什么 |
|---|---|---|---|
| a | 用户粘贴的参考文 / 往年作业 | 0 | 和指定文本比。最适合"和同学互查""和往届比" |
| b | 站内历史库（D1 存 shingle hash） | 低 | 站内互抄。**这是唯一能真正"建库查重"的路径** |
| c | 公网检索（Brave / Bing / Serper API） | 每次 ~0.003 美元，免费额度 2000 次/月 | 网上能搜到的。抽 8–12 个高熵 12–16 字片段，加引号搜索，命中页面再抓正文比对 |
| d | 商业库（知网/维普/Turnitin/iThenticate） | — | 个人拿不到 API，别在这上面花时间，如实告诉用户 |

### 2.4 指标与分档

```
总相似度 = 命中字数 / 有效字数（已剔除引用与参考文献）
另列：单源最高、多源累计、最长命中片段、改写相似度
```

| 总相似度 | 档位 |
|---|---|
| <10% | 低 |
| 10–20% | 中 |
| 20–35% | 偏高 |
| >35% | 高 |

UI 必须写明：**与学校系统不可比**。

## 4. Cloudflare 落地方案（三档，可渐进）

### Tier 1 —— 纯前端，0 成本，1 个文件（先做这个）

`ai-check.js`：`detectAI(text, opts)` + `compareTexts(text, refs[])`，零依赖，浏览器直接 `<script type="module">`。

- 能做什么：规则打分、高亮、和粘贴的参考文对比、段落热力
- 不能做什么：查全网、查站内历史
- 体积预算：≈600 行 / 约 18 KB min

### Tier 2 —— Worker 侧规则 + 公网检索

```
POST /api/ai-check      → Worker 跑同一套 rules（rules.js 内联进 worker.js）
POST /api/sim-search    → 抽片段 → Brave Search API → 抓命中页面 → 比对
```

- 注意 Worker 的 CPU 时间与子请求数：片段数 ≤8，并发 fetch，单次总超时 20s
- Key 放 Secret：`BRAVE_API_KEY`（或 `SERPER_API_KEY`）

### Tier 3 —— 站内库（要做"查重率"就必须有它）

```
D1   docs(id, owner_token, hash_blob, shingle_count, idf_ready, created_at, ttl)
R2   （可选）原文，仅用户显式同意时存，用于被抄袭追溯
Vec  sentence embeddings，做改写检测
```

- 新文 vs 库：MinHash 签名（128 维）+ LSH 分桶预筛，再做精确 containment
- **隐私**：默认只存 shingle 哈希集合（不可还原原文），TTL 90 天，页面上给"删除我上传的记录"按钮
- ⚠️ 现有 README 承诺"论文内容不落库、不留缓存"——启用 Tier 3 必须改这句承诺并明确告知

## 5. 性能

| 规模 | 耗时（前端实测预期） |
|---|---|
| 5,000 字 单篇 AI 打分 | <15 ms |
| 5,000 字 shingle 化（约 5,000 个） | <25 ms |
| 1 篇 vs 10 篇参考文 | <120 ms |
| 1 篇 vs 1,000 篇（LSH 预筛） | <400 ms |

超过 2 万字建议分块 Worker 侧跑，别卡主线程。

## 6. 合规与防误伤

1. **不自动判罚**：结果只作辅助，任何结论必须人工复核。全球检测器的误报率都在 5–15%，非英语母语写作者误报率显著更高——这一点必须在页面上写明。
2. **不宣称等同**：文案禁止出现"知网查重率""Turnitin 同款"。
3. **明确档位而非百分比**：`AI 风格 偏高（68/100）` ✔ ｜ `AI 生成率 68%` ✘。
4. **不要暴露完整权重表**（如果在意抗规避）。
5. **提示文本长度**：<300 字不出分。

### 实测分离度（4 段样本，193–378 字）

| 样本 | AI 风格指数 | 档位 |
|---|---|---|
| AI 腔中文 | 68 | 偏高 |
| 真人叙事中文 | 13 | 低 |
| AI 腔英文 | 61 | 偏高 |
| 真人叙事英文 | 21 | 低 |

查重：把一段 40 字的长句抄进正文，能定位出 2 个连续片段、算出 40.4%，位置精确到字。
性能：3,600 字全文 9.6 ms；确定性 PASS（同文本两次结果完全一致）。

### 与设计稿的两处偏离（都是实测后改的）

1. **指纹不用 FNV-1a**，直接用子串做 Map 的 key。短字符串在 V8 里会被驻留，比散列更快，而且零碰撞——省掉了校验碰撞的代码。规模到十万级字符再换哈希。
2. **语义改写检测没上 embedding**，第一版用「二元组 Jaccard > 0.5 且字面不重合」的启发式。它只能抓明显的换词洗稿，误报也会有一点，所以单独一栏、不计入重复率。等接上 `bge-m3` 再替换这一层。

### 还需要你做的

- **校准**：现在的权重和阈值是经验值。要更准，需要 120–200 篇标注样本（真人 60 / AI 60 / 混写 40），跑一遍逻辑回归重拟合 `RULES.weights`。没有样本之前，任何数字都只能当相对参考。
- **词表**：套话词表（中文 60 条 / 英文 43 条）覆盖的是 2024 前后常见的模型腔；新模型的口头禅要持续往里加。
